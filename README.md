# Maktab marketing website

A standalone, single-page website for Islamic school administrators. Plain HTML, CSS, and JavaScript; no runtime dependencies, bundler, API, or database.

## Run locally

From this directory, run `node preview.cjs` and open http://127.0.0.1:4175.

## Hosting

The website runs on Cloudflare Workers at https://maktab-marketing.luminarysolutions.ai (`wrangler.jsonc`). Pages and files are static assets in `public/`; `/features` serves `features.html`, `/waitlist` serves `waitlist.html` and unknown paths get `404.html`. Only `/api/*` runs the Worker (`src/index.js`). Deploy from this directory after `npx wrangler@4.140.0 login`:

```bash
npx wrangler@4.140.0 deploy
```

The custom domain is attached by the `routes` entry on deploy, and `public/_headers` sets security and cache headers.

## Pages

- `index.html`: the landing page.
- `features.html`: every feature area with real staging screens (captured 2026-10-12, demo school data). Claims are checked against the marketing briefs in the Maktab repository (`docs/marketing/01`–`09`).
- `waitlist.html`: the waitlist survey. Generated by `python tools/gen_waitlist.py` from `tools/waitlist.template.html`, taking every choice from `OPTIONS` in `src/index.js` so the page and the server agree. Change a choice there, then regenerate.

## Tour video

The home page plays the 89-second tour from `public/assets/video/` (1080p and a lighter 720p for phones, plus a poster). Nothing downloads until a visitor presses play, the native controls appear only once it plays, and the hero's "Watch the tour" link scrolls to it and starts it. Video requests go through the Worker (`run_worker_first` in `wrangler.jsonc`, `serveVideo` in `src/index.js`) because static assets answer a Range request with the whole file, and Safari will not play video without 206 byte ranges. Source: the hero cut in the Maktab repository (`docs/marketing/video/remotion`); re-encode with H.264 CRF 24 (1080p) and CRF 25 (720p), `+faststart`, AAC.

## Forms and email

`POST /api/contact` (home page) and `POST /api/waitlist` take JSON, are rate limited to 5 a minute per visitor, ignore bots (a hidden field and a minimum time on the page), store every submission in the D1 database `maktab-marketing-forms` (table `submissions`, `migrations/`) and email it to `CONTACT_TO` with the visitor as Reply-To.

Email goes through [Resend](https://resend.com) on its free plan, from `forms@maktab-staging.luminarysolutions.ai`, the domain already verified in the Resend account staging uses (the free plan allows one domain). The Worker needs one secret, a Resend API key with sending access:

```bash
npx wrangler@4.140.0 secret put RESEND_API_KEY
```

Without the key, submissions are still stored and the form still thanks the visitor; the failed send is logged. To change the inbox, edit `CONTACT_TO` in `wrangler.jsonc` and deploy. Read stored submissions with:

```bash
npx wrangler@4.140.0 d1 execute maktab-marketing-forms --remote --command "SELECT created_at, kind, name, email, school FROM submissions ORDER BY id DESC LIMIT 50"
```

Local testing: `npx wrangler@4.140.0 d1 migrations apply maktab-marketing-forms --local`, put `RESEND_API_KEY=...` in `.dev.vars` (git-ignored), then `npx wrangler@4.140.0 dev`. Local sends are real if the key is real.
